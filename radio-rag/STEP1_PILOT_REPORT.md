تاریخ: 2026-10-22 · وضعیت: **موفق** (پایلوت ۴۰ برنامه؛ آماده تصمیم برای اجرای کامل)

## خلاصهٔ یک‌خطی
یک نمونهٔ واقعی ۴۰‌برنامه‌ای را از MySQL + فایل‌های واقعی خواندم، به JSON استاندارد تبدیل
کردم، به ۷۵۰ chunk با timestamp واقعی تبدیلش کردم، با همان مدل امبدینگ که سرویس RAG
query از آن استفاده می‌کند (Qwen3-Embedding-0.6B / 1024) embed و در یک ایندکس **in-memory
غیرproduction** test کردم. پرسش واقعی فارسی، پاسخ را به **برنامه + زمان واقعی** راجع‌سازی
کرد. مقیاس کامل قابل‌اجراست: ~۵۹K chunk / ~۱۲۵MB / ~۵–۴۹ min embed / <۱.۵GB ES.

## ۳. JSON استاندارد (نسخهٔ ۱.۰)

فایل: `state/pilot_episodes.json` — یک doc به ازای هر برنامه. ساختار:

```json
{
 "schema_version": "1.0",
 "episode_id": "radio-maaref-03-08-13-23-30",
 "channel": "radio-maaref",
 "air": {"persian":"1404-03-08","gregorian":"2025-05-29","time":"13:23:30",
         "air_source":"time_description","created_at":"…"},
 "program": {"program_name":"پرسمان خانواده","program_description":"…",
             "program_time_description":"یکشنبه 21 اردیبهشت 1404 …"},
 "subtitles_raw": {"file":"downloads/<stem>.srt","bytes":…},
 "text_raw":      {"file":"downloads/<stem>.txt","bytes":…},
 "artifacts": {"full.txt":true,"correct.txt":true,"correct.srt":true,
               "summary.txt":true,"summary.en.txt":false},
```

تولیدشده جایگزین نمی‌شود.** آرتیفکت‌های LLM (full/correct/summary) فقط در صورت
وجود واقعی در `correct.srt` / `summary*.txt` خوانده می‌شوند.

## ۴. سیاست Chunking

- واحد بازیابی = **پنجره از بلوک‌های SRT پاک‌شدهٔ متوالی** در `<stem>.correct.srt`
- پارامترها: `MAX_CHUNK_CHARS=800` (محور اصلی) · `CHUNK_WINDOW_SEC=300` · `MIN_CHUNK_CHARS=200`
- هر chunk یک **citation** = نام برنامه + تاریخ پخش (FA+GR) + بازهٔ زمانی واقعی
  (مثل «پرسمان خانواده, air 1404-03-08 (2025-05-29), from 0:00:00 to 0:01:11»)
- یک chunk **summary** به ازای هر اپیزود (FA+EN) برای پرسش‌های سطح‌اپیزودی
- **بگ‌خام‌فیکس:** یک بلوک SRT معیوب که کل متن اپیزود را در خود داشت (تا 8929 کاراکتر)
  → در حد 2× سقف به‌طور اجباری بر اساس کلمه تقسیم می‌شود؛ حداکثر chunk حالا **956 کاراکتر**
  (قبل: 8929)

**خروجی:** `state/dump_v1.jsonl` — **750 chunk** (695 subtitle_window + 40 summary)،
611,478 کاراکتر، 1,580,435 بایت، `dump_sha256=e9145169…8fb9b9`

## ۵. مدل امبدینگ — تصمیم

| سؤال کاربر | پاسخ (تأییدشده) |
|---|---|
| 0.6B یا 4B؟ | **0.6B / 1024** — چون سرویس RAG query مشترک همین را استفاده می‌کند؛ 4B/2560 **ناسازگار** است و رادیو را از بانک Q&A مشترک خارج می‌کند |
| ابعاد | **1024** (cosine) |
| تأخیر | **~50 ms/chunk** (750 chunk در 32.7 s) |
| کیفیت فارسی | خوب — در test قطعی، chunk صحیح با فاصلهٔ محسوس (0.609) رتبهٔ اول |

**تست زندهٔ کیفیت بازیابی (in-memory، غیرproduction):**

```
Q: در برنامه پرسمان خانواده چه توصیه‌ای برای تقویت مهارت‌های ارتباطی با اعضای خانواده داده شد؟
[0.6092] subtitle_window  پرسمان خانواده, air 1404-03-08 (2025-05-29), from 0:00:00 to 0:01:11
         «تا برید با یه غریبه‌ی بیرون … با اعضای خانوادتون، با فامیلهاتون ارتباطتون رو بیشتر کنید …»
[0.5899] summary          پرسمان خانواده, air 1404-03-08 (2025-05-29)
         «توصیه‌های عملیاتی برای تقویت مهارت‌های ارتباطی … شروع تمرین از دایره‌ی نزدیک و قابل اعتماد مانند خانواده»
[0.4536] subtitle_window  سمت خدا, air 1404-02-21 (2025-05-11), from 0:27:56 to 0:29:15
```

→ **معیار موفقیت برآورده شد:** برنامهٔ جدید → JSON → dump → بازیابی با منبع پاسخ
قابل‌ردیابی = **برنامهٔ واقعی + زمان واقعی**.
